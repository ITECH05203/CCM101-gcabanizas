# Reflection

Completing this laboratory activity gave me a much clearer picture of what
actually makes up "the cloud." Before this, cloud computing felt abstract —
just a term for "someone else's computer." Investigating a real Linux
server and mapping its compute, storage, and networking resources to
concepts I'd only read about made the idea concrete.

Of the four infrastructure components, I think **compute** is the most
important, because it's the resource that actually does the work — running
applications, processing requests, and executing code. Without compute,
storage would just be inert data and networking would have nothing to
connect. Storage and networking support compute, but compute is what
turns infrastructure into a working service.

Linux supports cloud computing by acting as the operating system that
manages hardware resources efficiently and predictably across huge numbers
of virtual machines. Its open-source nature, stability, and strong
command-line tooling make it the standard choice for cloud providers to run
servers at scale, which is why almost every cloud instance I've encountered
in this course runs some Linux distribution.

Technical documentation is critical before deploying infrastructure because
it prevents mistakes, miscommunication, and wasted resources. A well-written
infrastructure report lets senior engineers, teammates, or clients understand
exactly what's being built and why, before money and time are spent
provisioning real servers. It also creates accountability — if something
goes wrong later, the documentation shows what was planned and decided.

The main new skills I learned in this activity were investigating a Linux
server's compute, storage, and networking details from the command line, and
translating that raw information into professional, client-facing
documentation. I also learned how to compare cloud providers using their own
official terminology, which will help me communicate cloud concepts more
accurately going forward.

My GitHub portfolio has improved significantly after this mission. It now
demonstrates not just basic Linux skills from Lab 1, but the ability to
investigate infrastructure, compare cloud providers, and produce structured
technical documentation — skills that closely resemble real responsibilities
of a junior cloud engineer.
